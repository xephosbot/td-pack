# TDLib JNI CMake Configuration Analysis

## Key Findings:

### 1. JNI Configuration Entry Point
File: td/CMakeLists.txt, Line 30
- Option: TD_ENABLE_JNI "Use \"ON\" to enable JNI-compatible TDLib API"

### 2. JNI Package Finding
File: td/CMakeLists.txt, Lines 1288-1295

```cmake
if (TD_ENABLE_JNI AND NOT ANDROID) # jni is available by default on Android
  if (NOT JNI_FOUND)
    find_package(JNI REQUIRED COMPONENTS JVM)
  endif()
  message(STATUS "Found JNI: ${JNI_INCLUDE_DIRS} ${JNI_LIBRARIES}")
  target_include_directories(tdapi SYSTEM PUBLIC ${JAVA_INCLUDE_PATH} ${JAVA_INCLUDE_PATH2})
  target_link_libraries(tdapi PUBLIC ${JAVA_JVM_LIBRARY})
endif()
```

### 3. Key CMake Variables
From CMake's FindJNI module:
- JNI_INCLUDE_DIRS: Include paths for jni.h
- JNI_LIBRARIES: All JNI libraries (JAWT and JVM)
- JAVA_INCLUDE_PATH: Primary Java include path
- JAVA_INCLUDE_PATH2: Secondary Java include path (platform-specific)
- JAVA_JVM_LIBRARY: The JVM library (typically libjvm.so or libjvm.dylib)

### 4. Link Chain

TARGET: tdjson (SHARED library)
  └─ PRIVATE: tdjson_private (STATIC)
       └─ PUBLIC: tdclient (STATIC)
            └─ PUBLIC: tdapi (STATIC)
                 ├─ PRIVATE: tdutils (STATIC)
                 └─ PUBLIC: ${JAVA_JVM_LIBRARY} ← **JVM LIBRARY HERE** (when TD_ENABLE_JNI=ON)

### 5. TDLib Source Impact
File: td/CMakeLists.txt, Lines 248-260
When TD_ENABLE_JNI OR ANDROID is set:
- Includes: td/tl/tl_jni_object.cpp, td/tl/tl_jni_object.h
- This adds JNI-compatible object handling to the API

### 6. Target Definitions

**tdapi** (STATIC) - Line 1284
- Includes JNI headers when TD_ENABLE_JNI enabled
- Links JAVA_JVM_LIBRARY publicly

**tdclient** (STATIC) - Line 1345
- Depends PUBLIC on tdapi (inherits JNI lib dependency)

**tdjson_private** (STATIC) - Line 1385
- Depends PUBLIC on tdclient (inherits JNI lib dependency through tdapi)

**tdjson** (SHARED) - Line 1397
- Depends PRIVATE on tdjson_private
- But since tdjson_private has PUBLIC dependency on JVM through tdapi, the JVM lib becomes part of tdjson's transitive dependencies

### 7. Android Exception
Line 1288: "if (TD_ENABLE_JNI AND NOT ANDROID)"
- On Android, JNI is available by default (NDK provides it)
- The find_package(JNI) is NOT called on Android

### 8. Java Example CMakeLists.txt
File: td/example/java/CMakeLists.txt, Lines 14-17, 86-87

```cmake
if (NOT JNI_FOUND)
  find_package(JNI REQUIRED COMPONENTS JVM)
endif()
message(STATUS "Found JNI: ${JNI_INCLUDE_DIRS} ${JNI_LIBRARIES}")

# In tdjni target:
target_include_directories(tdjni SYSTEM PRIVATE ${JAVA_INCLUDE_PATH} ${JAVA_INCLUDE_PATH2})
target_link_libraries(tdjni PRIVATE ${JAVA_JVM_LIBRARY})
```

### 9. Build Scripts
- build-tdlib-jni-linux.sh: Passes -DTD_ANDROID_JSON_JAVA=ON, targets tdjni, produces libtdjsonjava.so
- build-tdlib-jni-macos.sh: Passes -DTD_ANDROID_JSON_JAVA=ON, targets tdjni, produces libtdjsonjava.dylib
- build-tdlib-windows.ps1 (-EnableJni): Passes -DTD_ANDROID_JSON_JAVA=ON, targets tdjni, produces tdjsonjava.dll
- build-tdlib-linux.sh: Passes -DTD_ENABLE_JNI=OFF
- build-tdlib-ios.sh: Passes -DTD_ENABLE_JNI=OFF

All desktop JNI builds apply patches/custom-package-name.patch before configuring, which changes
PACKAGE_NAME from "org/drinkless/tdlib" to "io/xbot/tdlib".  The patch is reverted after the build.
CMAKE_SYSTEM_NAME is set explicitly (Linux/Darwin/Windows) on all arches to force CMake into the
if(CMAKE_CROSSCOMPILING) branch of the root CMakeLists.txt that builds the tdjni target.

## Cross-Compilation Problem

The issue is in td/CMakeLists.txt line 1290:
```cmake
find_package(JNI REQUIRED COMPONENTS JVM)
```

When cross-compiling:
1. CMake looks for JNI using the cross-compiler's paths
2. On the host system, it may not find the target architecture's JNI
3. The target-specific libjvm.so from the cross-compilation toolchain is not being found
4. This causes linking issues with cross-compiled targets

The CMAKE_FIND_ROOT_PATH mechanism (set in lines 30 and 70 of the root CMakeLists.txt)
should help but may not cover all JNI search paths.
